A bookmark manager for Emacs, that replaces the the built-in
~bookmark.el~. It is inspired by [[https://www.emacswiki.org/emacs/BookmarkPlus][bookmark+]].

It supports most of =bookmark+='s features: tags, non-file
bookmark types, temporary bookmarks, bookmark highlighting,
and others.

=bookmark-gt= is integrated with consult, marginalia, and
orderless.

Bookmark files created with =bookmark-gt= can be read by the
built-in bookmark package and by =bookmark+=.  =bookmark-gt=
can also read files created by either of those.

* Install

Using use-package with a local directory

#+begin_src emacs-lisp
(use-package bookmark-gt
  :straight nil
  :load-path "~/.emacs.d/modules/bookmark-gt"
  :bind (("C-x r m" . bookmark-gt-set)         ; supersede built-in bookmark-set
         ("C-x r l" . bookmark-gt-list)        ; supersede bookmark-bmenu-list
         ("C-x r b" . bookmark-gt-jump)        ; fuzzy jump reader
         ("C-x r u" . bookmark-gt-set-url))    ; new: bookmark a URL
  :config
  (bookmark-gt-mode 1))
#+end_src

Requires Emacs 30.1+.  Soft-deps (loaded when present, package works
without them):

- ~marginalia~ — bookmark completion annotator (tags · type · path).
- ~consult~ — jump reader UI (falls back to plain ~completing-read~).
- ~orderless~ — enables the ~,@type~ / ~;tag~ narrowing particles.
- ~browser-gt~ — required only for the browser-tabs feature. See below

The bindings above rebind the standard ~C-x r m~, ~C-x r l~,
and ~C-x r b~ to the bookmark-gt equivalents.  In particular:
prefer ~bookmark-gt-jump~ over the built-in ~bookmark-jump~
— the bookmark-gt reader adds type / tag narrowing, marginalia
annotations, MRU-first sort, and an active-tag filter chip
directly in the prompt.  Non-interactive callers should use
~bookmark-gt-jump~ (or its ~-other-window~ / ~-tagged~
variants) so those features are always available.

* Getting started

** Master switch: ~bookmark-gt-mode~

Global minor mode.  Enables every bookmark-gt feature; when
off, no advice or hook is installed and the built-in
~bookmark.el~ operates unmodified.

When enabled:

- *Set operations.*  ~bookmark-gt-set~ reads tags, applies
  the same-name policy, and assigns bookmark-gt's Dired
  handler when the current buffer is Dired.  Its name prompt
  starts out holding the suggested name — derived from the
  location being bookmarked, not from the last bookmark
  jumped to — as editable text: ~RET~ accepts it, point is at
  its end for a small edit, and ~C-a C-k~ replaces it.  Names matching
  ~bookmark-gt-auto-temp-names~ (e.g.
  ~org-capture-last-stored~) are marked temporary at store
  time, which excludes them from ~bookmark-save~ output.
- *Jump operations.*  Every jump increments the record's
  ~visits~ property and updates ~last-visited~.  File
  bookmarks display as line overlays in their visited
  buffers.  Region bookmarks reselect their region on jump.
  URL and browser-tab handlers suppress the built-in
  annotation-buffer display.
- *Jump reader.*  ~bookmark-gt-jump~ is the recommended
  replacement for the built-in ~bookmark-jump~.  It sorts
  candidates MRU-first using the ~visits~ / ~last-visited~
  values above, integrates with ~marginalia~ annotations
  and the ~consult~ / ~orderless~ narrowing particles
  (~,@TYPE~ / ~;TAG~) when those packages are loaded, and
  supports a mid-read tag filter (~M-t~ adds, ~M-d~ pops,
  ~M-D~ clears).
- *File-type dispatch.*  File bookmarks whose ~filename~
  matches a regexp in ~bookmark-gt-file-type-handlers~ are
  handled by the associated function instead of the built-in
  ~find-file~ path.
- *File-rename tracking.*  ~rename-file~ (including from
  Dired's ~R~) rewrites every bookmark whose ~filename~
  equals the source path to the destination.
- *Temp filter on save.*  Records carrying ~bmkp-temp~ are
  excluded from ~bookmark-save~ output; the live alist
  retains them for the session.

Disabling the mode removes every advice and hook that
enabling installed.  The three opt-in modes described below
(auto-update, default-tags, browser-tabs) each add further
behavior and are controlled independently.

** Opt-in modes

Three independent global minor modes, off by default.  Enable
each only if you use the feature.

*** ~bookmark-gt-auto-update-mode~

Bookmarks carrying the ~auto-update~ alist property get their
position refreshed to the visiting buffer's current point on every
idle tick.  Useful for e-readers, long-form documents,
~pdf-tools~ page tracking.

Triggers: an idle timer (~bookmark-gt-auto-update-interval~,
default 60 s), plus ~kill-buffer-hook~ and
~window-state-change-hook~ to capture buffer closes and window
switches without waiting for the next idle tick.  Pressing ~g~
in the list buffer also triggers a refresh before the buffer
redraws.

Toggle the property on the row at point with =^= in the list
buffer, or ~M-x bookmark-gt-auto-update-toggle NAME~.

*** ~bookmark-gt-default-tags-mode~

Seeds the tag reader on ~bookmark-gt-set~ with context-appropriate
tags.  Configured via a small DSL:

#+begin_src emacs-lisp
(setq bookmark-gt-default-tags "work")                    ; single tag
(setq bookmark-gt-default-tags '("work" "urgent"))        ; list
(setq bookmark-gt-default-tags                            ; function
      (lambda (record)
        (cond ((string-prefix-p "/proj/" (bookmark-gt-filename-of record))
               '("project"))
              ((eq (bookmark-gt-handler-type record) 'url)
               '("web"))
              (t nil))))
#+end_src

Errors in the function form are demoted to a warning; nothing
is applied without user confirmation.  The user always sees
the defaults as prefill in the tag reader and can edit or
clear them.

*** ~bookmark-gt-browser-tabs-mode~

Exposes the browser's open tabs as bookmarks (temporary — not
saved to disk).  Requires ~browser-gt~ to be installed and connected.

Refresh triggers:

- Every ~bookmark-gt-jump~ call.  The mode adds
  ~bookmark-gt-browser-tabs-refresh~ to
  ~bookmark-gt-jump-before-read-hook~, so the reader sees
  current tabs at each read.  Tab state changes faster than
  connect and disconnect events fire, and one fetch per jump
  is cheaper than a polling timer.
- Browser connect and disconnect events.  The mode subscribes
  to ~browser-gt-client-connected-functions~ and
  ~browser-gt-client-disconnected-functions~ and refreshes the
  tab records whenever a browser attaches or detaches.  Bursts
  of events within ~bookmark-gt-browser-tabs-debounce~ seconds
  (default 0.3) are coalesced into a single refresh.
- Mode enable: one refresh runs immediately when a browser is
  already connected.  When no browser is connected, the first
  refresh runs on the next connect event or the next jump.
- ~g~ (revert) in the ~*Bookmarks-gt List*~ buffer.
- ~M-x bookmark-gt-browser-tabs-refresh~ for a manual refresh.

Turning the mode off removes the connect and disconnect hooks
and the jump-before-read hook, cancels any pending debounced
refresh, and clears the tab records added by this mode.
Records owned by other browser-gt-related packages
(~browser-gt-tab-manager-bookmark-jump~ etc.) are left alone.

Deleting a browser-tab bookmark from the
~*Bookmarks-gt List*~ buffer removes only the bookmark record;
the browser tab itself stays open and the next refresh will
re-add the record.  Closing the tab in the browser is a
separate operation.  This matches the rest of bookmark-gt:
deleting a bookmark never touches the resource it points to
(no file is deleted, no buffer is killed, no URL is
un-visited).

The refresh loop let-binds ~bookmark-save-flag~ to nil and
suppresses the per-record tag prompt, so a full refresh runs
as a single batch without mid-batch auto-saves or user prompts.

Each stored tab record's ~last-visited~ is seeded from the
tab's ~:lastAccessed~ field (Chrome / Firefox report this as
the last time the tab was focused, in milliseconds since
epoch).  MRU sort in ~bookmark-gt-jump~ therefore orders tabs
by the browser's own last-focused ordering, and every pre-jump
refresh re-reads the field so the ordering tracks browser
activity rather than bookmark-gt jump history.

Customizable:

- ~bookmark-gt-browser-tabs-browsers~ — list of browser clients to
  query, nil = all connected.
- ~bookmark-gt-browser-tabs-filter~ — nil / regexp / predicate
  applied per tab before storing.
- ~bookmark-gt-browser-tabs-debounce~ — seconds to coalesce
  browser connect and disconnect events before triggering a
  refresh (default 0.3).

* User interface

** The ~*Bookmarks-gt List*~ buffer

~M-x bookmark-gt-list~ opens the buffer.  It is a
~tabulated-list-mode~ derivative — click a column header to
sort, press ~S~ for column-at-point sort, and ~s~ (specific to
bookmark-gt) to cycle the sort column through the marker and
data columns.

*** Columns

| Col | Header | Meaning                                                                             |
|-----+--------+-------------------------------------------------------------------------------------|
| 0   | ~*~    | Selection: ~*~ if marked with =m=, ~D~ if flagged for deletion with =d=, blank else |
| 1   | ~^~    | Auto-update: ~^~ if the record carries the ~auto-update~ prop, blank else           |
| 2   | ~t~    | Temp: ~t~ if the record carries ~bmkp-temp~, blank else                             |
| 3   | Name   | Truncated at ~bookmark-gt-list-name-width~ (default 32) with an ellipsis            |
| 4   | Type   | From the handler registry — File, URL, EWW, Dired, Info, Org, PDF, BrowserTab, Function, Sequence, Kmacro, BkView, ... |
| 5   | Group  | Aggregate category — Web, File, Doc, Code, Media, Other                             |
| 6   | Tags   | ~,~-joined, truncated at ~bookmark-gt-list-tags-width~ (default 24)                  |
| 7   | Loc    | ~filename~, or the URL if non-file                                                  |

The Name of a bookmark whose file no longer exists on disk
renders with a strikethrough (~bookmark-gt-face-missing-file~).
Remote (Tramp) paths are not probed — the existence check is
local only.

*** Keys

| Key   | Action                                                       |
|-------+--------------------------------------------------------------|
| ~RET~ | Jump                                                         |
| ~o~   | Jump in another window                                       |
| ~C-o~ | Same as ~o~                                                  |
| ~TAB~ | Preview in another window (leaves point in the list)         |
| ~m~   | Mark row (numeric prefix: mark N rows down)                  |
| ~d~   | Flag row for deletion                                        |
| ~x~   | Delete every flagged row (prompts for confirmation)          |
| ~u~   | Unmark row                                                   |
| ~U~   | Unmark every row                                             |
| ~^~   | Toggle ~auto-update~ on row                                  |
| ~T~   | Toggle temp on row                                           |
| ~H~   | Toggle display of temporary bookmarks in this buffer         |
| ~r~   | Rename bookmark                                              |
| ~R~   | Relocate (change filename or URL)                            |
| ~t e~ | Edit tags (editable comma-separated list; add and remove in one prompt) |
| ~t a~ | Add tags (sequential reader with completion; empty RET / M-RET ends)    |
| ~t r~ | Remove tags (sequential reader; completion restricted to the row's tags)|
| ~a~   | Edit annotation                                              |
| ~/~   | Filter (choose by-type / by-tag / by-name-regexp / unfilter) |
| ~s~   | Cycle sort column                                            |
| ~V~   | Reset view (sort → Name, clear filters, restore `bookmark-gt-list-default-show-temp`) |
| ~g~   | Revert: refresh browser tabs and auto-update positions (if their modes are on), then redraw |
| ~C-x C-s~ | Save the bookmark file (`bookmark-save`)                 |
| ~i~   | Inspect record (pretty-print alist in a popup)               |
| ~q~   | Quit                                                         |

Selection marks are stored in a buffer-local hash keyed by
record cons identity — they survive sort, revert, and
after-hook re-renders.

*** Persisting view state

The list buffer's sort column, ~show-temp~ toggle, and active
filters are preserved across repeated invocations of
~bookmark-gt-list~ within a session.

To also carry the view across Emacs sessions, set
~bookmark-gt-list-persist-state~ to a non-nil value.  When
enabled, the three values are written to
~bookmark-gt-list-state-file~ (default:
~(locate-user-emacs-file "bookmark-gt-list-state")~) on every
state-changing command and on ~kill-emacs-hook~, and re-read on
the next `bookmark-gt-list-mode' entry.

#+begin_src emacs-lisp
(setq bookmark-gt-list-persist-state t)
#+end_src

Selection marks and point are never persisted.  Use ~V~ or
~M-x bookmark-gt-list-reset-view~ to restore defaults; the
reset itself is persisted when the file is enabled.

** Jump to a bookmark: ~bookmark-gt-jump~

Recommended replacement for the built-in ~bookmark-jump~.
The same command binds naturally to ~C-x r b~ (see Install)
and is the entry point every other bookmark-gt UI (list
buffer, view bookmarks, external commands) routes through.
Interactive uses, key bindings, and Lisp callers that need
type / tag narrowing, MRU sort, or the mid-read tag filter
should call this instead of ~bookmark-jump~.

Uses ~consult--read~ when consult is loaded, falls back to
~completing-read~ otherwise.  Both accept two narrowing
particles when orderless is loaded:

- ~,@TYPE~ — narrow to bookmarks of TYPE (~url~, ~eww~, ~file~,
  ~dired~, ~info~, ~org~, ~pdf~, ~browser-tab~, ~magit~, ~help~,
  ~image~, ~epub~, or any registered/derived type).
- ~;TAG~ — narrow to bookmarks carrying TAG.

Mid-read tag filter:

- ~M-t~ — add a tag filter and restart the read.  Active
  filters are shown as labels in the prompt.
- ~M-d~ — pop the most recent tag filter.
- ~M-D~ — clear every active tag filter.

*** Elisp signatures

All three entry points take keyword arguments only:

#+begin_src emacs-lisp
(cl-defun bookmark-gt-jump
    (&key bookmark display-function bookmarks-list bookmarks-filter
          sort-by preselect))

(cl-defun bookmark-gt-jump-other-window
    (&key bookmark bookmarks-list bookmarks-filter sort-by preselect))

(cl-defun bookmark-gt-jump-tagged
    (&key tag bookmark bookmarks-list bookmarks-filter sort-by preselect))
#+end_src

- ~:BOOKMARK~ — bookmark name or record.  When nil, prompt.
- ~:DISPLAY-FUNCTION~ — a function of one argument (a buffer);
  passed to `bookmark-jump' as its display func.
- ~:BOOKMARKS-LIST~ — alist to use as the candidate pool.
  Defaults to `bookmark-alist'.  Ignored when ~:BOOKMARK~ is
  supplied.
- ~:BOOKMARKS-FILTER~ — predicate on a record; a candidate is
  kept when the predicate returns non-nil.  Ignored when
  ~:BOOKMARK~ is supplied.
- ~:SORT-BY~ — ~mru~ (by ~last-visited~ desc), ~visits~ (by
  ~visits~ desc), or nil (preserve pool order).  Defaults to
  ~bookmark-gt-jump-default-sort~ (~mru~ by default).
- ~:PRESELECT~ — positive integer.  When set (and vertico is
  loaded), the reader positions the cursor on the N-th
  candidate via a one-shot minibuffer-setup hook.  Useful for a
  "jump back to previous" workflow: with MRU sort and
  ~:preselect 1~, RET selects the second-most-recent record.
- ~:TAG~ (required for ~-tagged~) — string seeding the reader's
  active tag filter.

Candidate row layout is customizable via
~bookmark-gt-jump-candidate-format-function~ (default:
~bookmark-gt-jump-candidate-default~).  A custom function
receives the record and must return a propertized string with
the ~bookmark-gt-name~, ~consult--type~, and (optional)
~bookmark-gt-particles~ text properties — see the default
function's docstring for the contract.

Examples:

#+begin_src emacs-lisp
;; Jump directly to a known bookmark
(bookmark-gt-jump :bookmark "my-bookmark")

;; Jump with a custom display function (other-frame etc.)
(bookmark-gt-jump :display-function #'switch-to-buffer-other-frame)

;; Prompt but only among file bookmarks
(bookmark-gt-jump :bookmarks-filter #'bookmark-gt-handler-file-p)

;; Prompt among a custom subset alist
(bookmark-gt-jump :bookmarks-list my-project-bookmarks)

;; Prompt among project files tagged "urgent"
(bookmark-gt-jump-tagged :tag "urgent"
                         :bookmarks-filter #'bookmark-gt-handler-file-p)
#+end_src

** Non-file bookmark types

*** URL bookmarks — ~bookmark-gt-set-url~

Interactive:

#+begin_example
M-x bookmark-gt-set-url RET
URL: https://example.org RET
Bookmark name: Example RET
#+end_example

Elisp:

#+begin_src emacs-lisp
(bookmark-gt-set-url "https://example.org" "Example" '("web" "reference"))
#+end_src

The URL bookmark's handler (~bookmark-gt-handler-url-jump~) opens
the URL via ~browse-url~.

*** Dired bookmarks — ~bookmark-gt-handler-dired-jump~

The built-in ~dired.el~ does not provide a bookmark handler.
bookmark-gt provides one that opens the recorded target and
restores the buffer state.  The setter captures, and the jump
handler restores:

- ~dired-directory~ — the original value, so plain paths,
  wildcard patterns (e.g. ~/tmp/*.el~), and explicit file lists
  round-trip verbatim;
- ~dired-marked~ — files marked in the buffer, keyed by mark
  character (uses ~dired-remember-marks~ /
  ~dired-mark-remembered~ — the same primitives bookmark+
  uses);
- ~dired-subdirs~ — subdirectories inserted with ~i~;
- ~dired-hidden-dirs~ — subdirectories currently hidden (~$~);
- ~dired-switches~ — ~dired-actual-switches~ in effect.

The alist keys match bookmark+'s (~bmkp-jump-dired~), so
records interchange on disk in either direction: a Dired
bookmark written by bookmark+ restores under bookmark-gt with
all its state, and vice-versa.  Records with the bookmark+
handler symbol classify as Dired via the registry alias; you
can also convert them to bookmark-gt form with
~M-x bookmark-gt-migrate-from-bookmark-plus~ (see
[[Migrating from bookmark+]]).

**** Virtual dired

Setting a bookmark from a virtual-dired buffer (~M-x
dired-virtual~ or the ~V~ command in ~dired-x~) additionally
inlines the buffer's textual listing under a ~dired-listing~
key, and marks the record with ~dired-virtual t~.  On jump,
the handler creates a fresh buffer, inserts the listing, and
calls ~dired-virtual~ to reconstruct the same view — even if
the source directory no longer exists.

This is not a bookmark+ compatibility feature: bookmark+ does
not preserve virtual-dired contents and re-opens the recorded
directory as real dired.  The bookmark-gt behavior is opt-in
via the buffer being virtual; you do nothing special to set
one.

The listing is bounded by
~bookmark-gt-dired-virtual-max-size~ (bytes; default 524288 =
512 KB).  Setting a larger virtual-dired buffer signals
~user-error~ — raise the cap in the defcustom, or bookmark a
smaller portion.  The rationale for the cap: the bookmark
file is loaded whole at startup and rewritten whole on every
save, so an inlined multi-megabyte listing multiplies that
cost on every unrelated bookmark change.

*** Function bookmarks — ~bookmark-gt-set-function~

A function bookmark stores a callable (a symbol or lambda)
under the ~function~ alist key.  Jumping invokes the callable.

Interactive:

#+begin_example
M-x bookmark-gt-set-function RET
Function bookmark name: rebuild-project RET
Function to call on jump: my-project-rebuild RET
#+end_example

Elisp:

#+begin_src emacs-lisp
(bookmark-gt-set-function "rebuild" #'my-project-rebuild)
(bookmark-gt-set-function "flip-theme"
                          (lambda () (my-toggle-theme)))
#+end_src

*** Keyboard-macro bookmarks — ~bookmark-gt-set-kmacro~

A kmacro bookmark stores a key-event vector under the
~kmacro~ alist key and replays it on jump via
~execute-kbd-macro~ (with ~current-prefix-arg~ as the repeat
count).

Interactive: prompts for the macro via a single completion
whose candidates are the current named keyboard macros plus
a ~[last-kbd-macro]~ sentinel that stands for the anonymous
most-recent macro.  The sentinel is the default when
~last-kbd-macro~ is defined; otherwise the first named macro
is the default.  Errors when neither exists.

Named keyboard macros are any symbols whose ~symbol-function~
is a string or vector, or which carry a ~kmacro~ property (as
produced by ~M-x kmacro-name-last-macro~).

Elisp:

#+begin_src emacs-lisp
(bookmark-gt-set-kmacro "type-hi" [?h ?i])
(bookmark-gt-set-kmacro "type-abc" "abc")   ; parsed by `read-kbd-macro'
#+end_src

Unlike bookmark+, which overloads the function-bookmark
handler (its ~bmkp-jump-function~ dispatches by payload type),
bookmark-gt gives kmacros their own type and handler so the
list buffer, narrow, and filter can distinguish them.
Trade-off: kmacro records are NOT interchangeable on disk with
bookmark+ (a bookmark+ macro record still classifies as Function
under bookmark-gt because the record's handler symbol is
~bmkp-jump-function~).

*** Sequence bookmarks — ~bookmark-gt-set-sequence~

A sequence bookmark stores a list of bookmark names under the
~sequence~ alist key.  Jumping visits each in order via
~bookmark-jump~.

Interactive: prompts for the sequence name, then reads
existing bookmark names one at a time until you enter empty
input.

Elisp:

#+begin_src emacs-lisp
(bookmark-gt-set-sequence "morning-workspace"
                          '("inbox" "todo.org" "calendar"))
#+end_src

*** File-type handlers — override the file-jump path per pattern

~bookmark-gt-file-type-handlers~ is an alist mapping a
filename regexp to a bookmark handler function.  When jumping
a file bookmark whose ~filename~ matches, the mapped function
is called with the bookmark record instead of the built-in
~find-file~ path.  The function's contract is the same as any
`bookmark.el' handler: one argument, the record.

Typical use: open certain file types with an external program
instead of an Emacs buffer.

#+begin_src emacs-lisp
(defun my-mac-open (bookmark)
  "Open BOOKMARK's file with macOS's `open' command."
  (call-process "open" nil 0 nil
                (bookmark-prop-get bookmark 'filename)))

(setq bookmark-gt-file-type-handlers
      '(("\\.pdf\\'"          . my-mac-open)
        ("\\.\\(mp4\\|mkv\\)\\'" . my-mac-open)))
#+end_src

Entries are tried in list order; the first matching regexp
wins.  The advice on ~bookmark-default-handler~ is installed
by ~bookmark-gt-mode~ and removed when the mode turns off.

*** View bookmarks — save the list buffer's current view

A view bookmark captures the presentation state of the
~*Bookmarks-gt List*~ buffer — active filters, sort key, and
the show-temp toggle — under the ~filters~, ~sort-key~, and
~show-temp~ alist keys.  Jumping opens the list buffer (if
needed), restores the state, and redraws.

To save: open the list, set the filters/sort/show-temp you
want, then ~M-x bookmark-gt-set~.  The list mode installs
its own ~bookmark-make-record-function~, so the standard set
command captures a view record automatically — no dedicated
command is needed.  Marks and point are intentionally not
saved; they are per-session, not part of the view.

Elisp: construct the record via ~bookmark-gt-set-non-file~
with handler ~bookmark-gt-handler-view-jump~ and the three
props; see ~bookmark-gt-list--make-record~ for the shape.

* Setting bookmarks

** Tag reader

~bookmark-gt-tags-read~ prompts for tags one at a time.  Each
prompt is a plain ~completing-read~ against every tag that
currently appears in ~bookmark-alist~, ordered
most-recently-used first (based on ~bookmark-gt-tags-history~;
completion history is the MRU signal).

Terminators:
- Empty ~RET~ — finish, return the accumulated list.
- ~M-RET~ — submit the current input (if non-empty), then finish.

Any non-empty ~RET~ accepts the current tag and prompts for
another.  The running accumulator is shown in the prompt as
~Tags [foo,bar] (M-RET or empty RET to finish): ~.

The reader is invoked by ~bookmark-gt-set~ when
~bookmark-gt-prompt-for-tags-flag~ is non-nil (default) and
seeds itself with any tags provided by
~bookmark-gt-default-tags-mode~ or another
~bookmark-gt-set-tag-reader-hook~ contributor.

** Same-name policy

Setting a bookmark whose name is already in use is not an
error.  The name the new record ends up stored under is
determined by these rules, in order:

1. *Prefix-argument override.*  When ~M-x bookmark-gt-set~ is
   called with a prefix argument (~NO-OVERWRITE~ non-nil from
   Lisp), a ~<N>~ suffix is always appended.  Same semantics
   as built-in ~bookmark-set~ with ~C-u~.
2. *Update in place.*  If ~bookmark-gt-same-name-overwrite~ is
   non-nil (the default) and the existing record has the same
   handler AND the same filename as the new one, the existing
   record is replaced in place.  This is the "update this
   bookmark's location" case: re-setting ~todo~ inside
   ~todo.org~ when ~todo~ already points to ~todo.org~ moves
   the existing record's position to point.
3. *Shared name across records.*  If
   ~bookmark-gt-allow-duplicate-names~ is non-nil (the
   default), the new record is stored under the literal name
   even when another record already uses it — two bookmarks
   in different files (or with different handlers) can share
   the same name.  Example: a ~todo~ bookmark in each of
   several project files.
4. *Fallback.*  With both flags off, any collision that isn't
   handled by rule 2 receives a ~<N>~ suffix.

*Caveat on rule 3.*  Emacs's ~bookmark-jump NAME~ and
~bookmark-get-bookmark NAME~ return the first alist match.
When two records share a name, only one is reachable that
way; the others still appear in ~bookmark-gt-list~ and
~bookmark-gt-jump~ (both iterate the alist directly and
distinguish records by the Location column).  Set
~bookmark-gt-allow-duplicate-names~ to nil if name-based
lookup matters more to you than shared names.

** Relocate: change a bookmark's target

~M-x bookmark-gt-relocate NAME~ changes where an existing
bookmark points, dispatching on the record's shape:

- File records (a ~filename~ key) prompt via ~read-file-name~;
  default is the current filename so a rename is a matter of
  editing.  ~position~ is left unchanged — the common trigger
  is a file rename, and the offset is still valid.
- URL records (a ~url~ key: URL bookmarks, browser-tab
  bookmarks) prompt for the new URL via ~read-string~.
- Records with neither key raise a ~user-error~.

In the list buffer, ~R~ relocates the row's record.  The
after-hook fires so the list, highlight overlays, and any
other observer refresh automatically.

For a genuinely new position within a different file, jump to
the target, place point, and re-invoke ~bookmark-gt-set~ with
the same name — the same-name-overwrite policy (above) updates
~position~ in place.

* In-file behaviors

** In-buffer cycling

Two autoloaded commands iterate over the bookmarks whose file
matches the current buffer's file, sorted by position:

- ~M-x bookmark-gt-cycle-next~ — jump to the next bookmark
  position after point.
- ~M-x bookmark-gt-cycle-prev~ — jump to the previous one.

Both wrap around at the ends of the sequence.  Print the
bookmark's name via ~message~ so the destination bookmark is
identified.  No overlay dependency — cycling uses record data
directly, so it works whether or not
~bookmark-gt-highlight-enable~ is on.

Records without a numeric ~position~ (e.g. Dired records) are
skipped; bookmarks pointing at other files are ignored.

Convenient bindings (in your init):

#+begin_src emacs-lisp
(global-set-key (kbd "C-c n") #'bookmark-gt-cycle-next)
(global-set-key (kbd "C-c p") #'bookmark-gt-cycle-prev)
#+end_src

** Per-bookmark highlighting

When ~bookmark-gt-mode~ is on, every file-visiting buffer gets
an overlay per bookmark that points at that file.  Overlays
use ~bookmark-gt-face-highlight~ (inherits ~hl-line~ by
default) and span:

- The bookmark's line, for point bookmarks.
- The whole region (from ~position~ line-start to
  ~end-position~ line-end), for region bookmarks.

Hovering shows the bookmark name via ~help-echo~.

Triggers:
- ~find-file-hook~ creates overlays as files are opened.
- ~bookmark-gt-set-after-hook~ refreshes overlays after any
  mutation.  Targeted single-file refresh when the mutation
  affects a specific record; full refresh only when a batch
  operation runs the hook with the ~nil~ sentinel.
- ~bookmark-after-jump-hook~ records the point after the jump
  in a buffer-local hash so records that carry no numeric
  ~position~ (e.g. org-heading bookmarks, whose target is
  resolved by ~org-bookmark-heading-jump~ at jump time) still
  get an overlay after the user visits them.  The recorded
  position is consulted by
  ~bookmark-gt-highlight--effective-position~ as a fallback
  when ~position~ is absent.

Customization:
- ~bookmark-gt-highlight-enable~ (default ~t~) — opt out.  Set
  to nil to suppress highlighting even while the mode is on.
- ~bookmark-gt-face-highlight~ — face for the overlay.
  Rebind to a subtler / stronger color as you prefer.

Overlays are process-scoped display state; they are removed
when the buffer is killed, and are cleared entirely when
~bookmark-gt-mode~ turns off.  Nothing is written to disk.
The post-jump position hash is likewise buffer-local and
transient.

** Region bookmarks

When ~bookmark-gt-mode~ is on and the region is active on
~M-x bookmark-gt-set~, the record captures both anchors plus
context strings so the region can be re-selected on jump:

- ~position~ = ~(region-beginning)~
- ~end-position~ = ~(region-end)~
- ~front-context-region-string~ = ~N~ characters preceding
  ~end-position~ (for re-anchoring)
- ~rear-context-region-string~ = ~N~ characters following
  ~end-position~
- ~front-context-string~ / ~rear-context-string~ = the built-in
  standard re-anchor strings around the start

Alist-key names match bookmark+ so records round-trip losslessly.
The built-in ~bookmark.el~ ignores the extra keys and jumps to
~position~ only.

On jump, a hook on ~bookmark-after-jump-hook~ pushes the mark
at ~end-position~ (adjusted by the delta between the record's
raw ~position~ and the actual point after built-in re-anchoring)
and activates it — the region reappears highlighted.

Customization:
- ~bookmark-gt-use-region~ (default ~t~) — opt out of capture
  and restore.  Records that already carry region info keep it;
  this flag only gates the set/restore paths.
- ~bookmark-gt-region-context-size~ (default 40) — chars of
  context captured around ~end-position~.

* Trackers

** Visit tracker

When ~bookmark-gt-mode~ is on, an entry on
~bookmark-after-jump-hook~ increments each jumped bookmark's
~visits~ property by one and refreshes its ~last-visited~ prop
to the current time.  The hook runs on every jump, including
jumps handled by URL and browser-tab handlers.

Enables ~:sort-by 'mru~ and ~:sort-by 'visits~ in the jump
reader for every bookmark type without user action.

Visit tracking does NOT bump ~bookmark-alist-modification-count~,
so a jump does not trigger an auto-save.  Changes persist to
disk at the next explicit ~bookmark-save~ (or on Emacs exit).

** File-rename tracker

When ~bookmark-gt-mode~ is on, an ~:around~ on ~rename-file~
rewrites any bookmark whose ~filename~ matches the source path
to the destination.  Intercepts Dired renames (~R~) as well,
since Dired uses ~rename-file~ internally.

Two guards:

- ~bookmark-gt-track-renames~ — user opt-out, default ~t~.  Set
  to nil to disable tracking entirely; the flag is read at call
  time so changes take effect immediately.
- ~backup-file-name-p~ on the destination — always skipped.
  Emacs's default save mode renames ORIG → ORIG~ before writing
  new content; without this guard the bookmark would follow the
  rename and end up pointing at your backup file.

Directory renames update only bookmarks whose ~filename~ equals
the directory exactly.  Children are NOT rewritten.

* Extension API

** Handler registry

~bookmark-gt-handler-alist~ is a flat alist keyed by handler
symbol.  Each entry:

#+begin_src emacs-lisp
(HANDLER . (:type TYPE-SYMBOL :name STRING :group GROUP-SYMBOL
            :face FACE :narrow-char CHAR :doc STRING))
#+end_src

Multiple handler symbols may share the same ~:type~ (URL has
three handler-symbol aliases, browser-tab has two, etc.).
Entries are included for: file, URL, EWW, Dired, Info, Org,
PDF, browser-tab, Magit, Help, Image, EPUB (nov.el).

Register a new handler (or an alias for an existing type):

#+begin_src emacs-lisp
(bookmark-gt-handler-register
 '(my-custom-jump my-legacy-jump-handler)
 (list :type 'custom :name "Custom" :group 'other
       :face 'bookmark-gt-face-file :narrow-char ?c
       :doc "My custom bookmark type."
       :preview #'my-preview-fn))   ; optional
#+end_src

The optional ~:preview~ key overrides what
~bookmark-gt-list-preview~ (bound to ~TAB~ in the list buffer)
does for that handler.  Called with the record; runs inside
~save-selected-window~ so it can pop up a preview buffer
without moving point away from the list.  When absent, preview
falls back to ~bookmark-jump-other-window~ on the record's own
jump handler — the current default.  Useful for e.g.
rendering a URL in an EWW buffer as preview while ~RET~ still
opens the external browser.

Unknown handler symbols are auto-classified via a fallback that
strips common suffixes (~-bookmark-jump-handler~, ~-bookmark-jump~,
~-jump-handler~, ~--handle-bookmark~) and title-cases the leading
segment.  So ~foo-bookmark-jump~ shows up as type "Foo" without
any registration.  Its group defaults to ~other~.

Type predicates — one per registered type:
~bookmark-gt-handler-file-p~, ~-url-p~, ~-eww-p~, ~-dired-p~,
~-info-p~, ~-org-p~, ~-pdf-p~, ~-browser-tab-p~, ~-magit-p~,
~-help-p~, ~-image-p~, ~-epub-p~, ~-function-p~,
~-sequence-p~, ~-kmacro-p~, ~-view-p~.  Each does
~(eq (bookmark-gt-handler-type record) 'TYPE)~.

** Group registry

Groups aggregate multiple types so users can filter or narrow
by an aggregate category (e.g. "web" covers URL + EWW +
browser-tab) rather than one type at a time.

Groups are DERIVED from the handler registry at classification
time — they are not stored on the record, never written to disk.

Six built-in groups are provided:

| Symbol | Name  | Narrow char | Types                               |
|--------+-------+-------------+-------------------------------------|
| ~web~  | Web   | ~w~         | url, eww, browser-tab               |
| ~file~ | File  | ~f~         | file, dired                         |
| ~doc~  | Doc   | ~d~         | info, org, pdf, help, epub          |
| ~code~ | Code  | ~c~         | magit                               |
| ~media~ | Media | ~m~         | image                               |
| ~other~ | Other | ~o~         | catch-all for unregistered handlers |

~bookmark-gt-group-alist~ is the registry (group symbol →
:name/:narrow-char/:doc plist).  Register a new group:

#+begin_src emacs-lisp
(bookmark-gt-group-register
 'science '(:name "Sci" :narrow-char ?s
            :doc "Science / research bookmarks."))
#+end_src

The list buffer shows a ~Group~ column (after ~Type~).  The
consult jump reader narrows by group — pressing ~w SPC~ shows
every web bookmark regardless of type.  Per-type filtering
remains available via the ~,@TYPE~ orderless particle.  Filter
in the list via ~/~ → ~by-group~.

Accessor: ~(bookmark-gt-handler-group RECORD)~ returns the group
symbol (or ~other~ when the handler is unregistered).

** Extension points

Every non-trivial mechanism is expected to have an extension point:

- ~bookmark-gt-set-name-reader-hook~ — runs once inside
  ~bookmark-gt-set~, before the name prompt is displayed to the
  user.  Each hook is called with ~(default-name context)~ and
  returns either a string (which replaces the default) or nil
  (to defer).  The first non-nil return wins.
- ~bookmark-gt-set-tag-reader-hook~ — runs once inside
  ~bookmark-gt-set~ and ~bookmark-gt-set-non-file~, after the
  name is chosen and before the record is stored.  Chained:
  each hook is called with ~(record seed-tags)~ and returns a
  new seed-tags list, which becomes the input to the next hook.
  ~bookmark-gt-default-tags-mode~ registers here to seed the
  list from context; the interactive tag reader registers here
  to prompt the user for edits.
- ~bookmark-gt-set-after-hook~ — runs at the end of every
  bookmark-record mutation: create (~bookmark-gt-set~,
  ~-set-non-file~), rename, tag edit, annotation edit,
  relocate, toggle-temp, toggle-auto-update, and delete.
  Called with the ~(name . data)~ pair.  bookmark-gt's own list
  buffer refresh does NOT go through this hook — it is wired
  directly.  Third-party observers register here to react to any
  change.
- ~bookmark-gt-jump-before-read-hook~ — runs once inside
  ~bookmark-gt-jump~, ~bookmark-gt-jump-other-window~, and
  ~bookmark-gt-jump-tagged~, immediately before the reader
  displays.  Fires only when the entry point is going to
  prompt the user (i.e. ~:BOOKMARK~ was not supplied) and does
  not re-fire on tag-filter restart within the same call.
  Called with no arguments; each function runs synchronously in
  the order added.  ~bookmark-gt-browser-tabs-mode~ registers
  ~bookmark-gt-browser-tabs-refresh~ here so live browser tabs
  are current at each read.  Register your own pool refreshers
  (auto-update sweep, remote-tab poll, ...) here.
- ~bookmark-gt-filter-alist~ — filter registry for the list
  buffer's ~/~ command.
- ~bookmark-gt-sort-alist~ — sort registry (includes name and
  type entries).

* Compatibility

** Data compat with bookmark+

By design, bookmark-gt reads and writes alist entries under the
same keys bookmark+ uses so files round-trip both ways:

| Key            | Meaning              |
|----------------+----------------------|
| ~tags~          | List of tag strings                       |
| ~bmkp-temp~     | Temp-record marker                        |
| ~auto-update~   | Auto-tracking flag                        |
| ~visits~        | Visit count                               |
| ~last-visited~  | Last visit timestamp                      |
| ~created~       | Record creation timestamp                 |
| ~last-modified~ | Record last-mutation timestamp            |

Two shape differences we accommodate on read:

- Bookmark+ writes the placeholder string ~"   - no file -"~ into
  ~filename~ for non-file records.  ~bookmark-gt-filename-of~
  treats it as nil.  Bookmark-gt records omit ~filename~ entirely
  for non-file records.
- Bookmark+ URL records store the URL under ~location~.
  Bookmark-gt writes it under ~url~.  Both are read by
  ~bookmark-gt-url-of~.

** Migrating from bookmark+

Records saved by bookmark+ carry handler symbols
(~bmkp-jump-dired~, ~bmkp-jump-url-browse~,
~bmkp-jump-url-browse-other-window~,
~bmkp-gt-browsel-tabs-jump~) that are unbound when bookmark+
is not loaded.  bookmark-gt registers these symbols as
classification aliases so the list buffer's Type column and
the jump reader's narrow menu work regardless — but jumping
still calls ~(funcall <symbol> record)~ and fails when the
function is not defined.

Fix once with ~bookmark-gt-migrate~:

#+begin_src emacs-lisp
;; One-time; not autoloaded — load explicitly.
(require 'bookmark-gt-migrate)
;; Preview mutates `bookmark-alist' in memory only.
(bookmark-gt-migrate-from-bookmark-plus)
;; Inspect via `M-x bookmark-gt-list' — verify the migrated
;; rows show the expected Type and jump correctly — then commit:
(bookmark-save)
#+end_src

What the migration does per record:

- Rewrites the ~handler~ symbol to the bookmark-gt equivalent.
- For URL records, copies ~location~ to ~url~ (bookmark-gt's
  convention) and drops ~location~.
- Strips bookmark+ bookkeeping props that have no bookmark-gt
  meaning: ~bmkp-gt-load-index~, ~buffer-name~,
  ~front-context-region-string~,
  ~rear-context-region-string~, empty ~annotation~, empty
  ~tags~.
- Preserves ~filename~, ~position~, ~front-context-string~,
  ~rear-context-string~, ~visits~, ~last-visited~, ~created~,
  ~last-modified~.
- Preserves the Dired state keys ~dired-directory~,
  ~dired-marked~, ~dired-subdirs~, ~dired-hidden-dirs~,
  ~dired-switches~ — bookmark-gt's Dired handler consumes
  them the same way bookmark+ did.

Records already in bookmark-gt form (or plain file bookmarks
with a nil handler) are left untouched.  Keep a copy of the
bookmark file before running.
